# GitHub Pages image diagnosis

The public repository URL is served from `/khairy-digital-profile/`, while runtime image strings in `client/index.html` and `Home.tsx` use root-absolute paths such as `/assets/...` and `/manus-storage/...`. The standalone Pages workflow builds with `base: /khairy-digital-profile/` and does not register the Express storage proxy, so `/manus-storage/...` cannot resolve there. The repository does contain local fallback assets under `client/public/assets/`, but the runtime code does not consistently prepend the Vite base path or select those fallbacks. The fix should use a shared base-aware public-asset helper for the mark, portrait, cover, and project fallbacks, while preserving signed/managed URLs in the Full-Stack preview. The oversized category headings are produced by `.work-heading-card` styles in `client/src/index.css`; replacing that visual treatment with a slim text row can be done in the shared `WorkShowcase` markup and styles, including dark and mobile overrides.
