# Production Schema Migration

يجب أن يبقى `drizzle/schema.ts` هو مصدر تعريف الجداول. عند إضافة أو تعديل جداول المصادقة أو محتوى الملف الشخصي، تُولَّد migration من جذر المشروع بواسطة `pnpm drizzle-kit generate`، ثم تُراجع ملفات SQL الناتجة قبل تطبيقها على قاعدة الإنتاج.

قبل التطبيق، يجب توفير `DATABASE_URL` لبيئة الإنتاج مع اتصال مشفر، وأخذ نسخة احتياطية وفق سياسة مزود قاعدة البيانات. تُطبَّق migration بعد مراجعة ترتيب الإنشاء والمفاتيح والعلاقات، ولا تُستخدم أوامر حذف جداول أو أعمدة في عملية النشر إلا بعد موافقة صريحة وخطة استرجاع.

بعد التطبيق، تُجرى قراءة تحقق غير مدمرة لجداول `users` وملفات المحتوى، ثم تُشغّل `pnpm test` و`pnpm check` و`pnpm build`. مسار OAuth يعتمد على وجود جدول `users` لأن callback يحفظ أو يحدّث المستخدم ثم ينشئ جلسة. لا تُحفظ ملفات البيئة أو قيم الأسرار داخل GitHub.

## التسلسل التشغيلي

| المرحلة | الإجراء | التحقق |
|---|---|---|
| 1 | تعديل `drizzle/schema.ts` | مراجعة التغيير والعلاقات |
| 2 | تشغيل `pnpm drizzle-kit generate` | قراءة SQL الناتج كاملًا |
| 3 | تطبيق SQL عبر أداة إدارة قاعدة البيانات المعتمدة | عدم وجود أخطاء أو عمليات destructive غير مقصودة |
| 4 | فحص غير مدمّر لجداول auth والمحتوى | وجود `users` والجداول المطلوبة |
| 5 | تشغيل الاختبارات والفحص والبناء | نجاح Vitest وTypeScript وVite |
| 6 | نشر checkpoint بعد التحقق | تسجيل رقم الإصدار وخطة rollback |
